琴悦文档优先级清单，分必须、建议和可选三档

文档 状态 原因 / 说明
已有
产品设计文档 v2.0页面、交互、状态、弹窗、文案规范 已完成 当前这份文档。建议在每个核心功能模块补充「验收标准」和「成功指标」字段，避免单独写 PRD。
必须 · 上线前不可缺少
API 接口文档所有后端接口的请求/响应定义 必须 前后端分离开发的唯要契约。没有它，前端只能猜后端返回什么，联调阶段会大量返工。建议用 OpenAPI 3.0（Swagger）格式，重点先写：用户认证、乐谱上传/识别、Stripe 支付三块。
数据库设计文档核心表结构、字段、关系、索引 必须 数据库结构一旦上线有数据就很难重构。必须在开发前敲定核心表设计，避免后期付出高昂迁移成本。用 ER 图 + 字段说明表呈现。
技术架构文档系统架构、技术选型、部署方案 必须 确定前后端框架、云服务商、OCR 服务方案、MusicXML 渲染库等核心选型。这些决策一旦开始开发就很难推翻，必须前置讨论并形成文档。
安全设计文档认证鉴权、支付安全、数据保护 必须 接入 Stripe 支付必须满足 PCI DSS 基础要求。用户数据加密、JWT 方案、API 鉴权、CSRF 防护等需要在开发前设计好。安全问题上线后修复成本极高。
上线评审 Checklist上线前所有检查项逐条确认 必须 不是叙述性文档，是一张逐项打勾的清单。包含：HTTPS 强制、Stripe Webhook 测试通过、版权声明上线、错误监控接入、备份验证、隐私政策发布等。防止上线时遗漏关键项。
部署方案 & 回滚预案CI/CD 流程、环境配置、应急回滚 必须 上线出问题时，没有预案就只能临时救火，往往越救越乱。必须在上线前演练过一次回滚流程，并记录成文档。
测试用例文档核心功能的功能测试、边界测试 必须 不需要覆盖所有场景，但支付流程、乐谱上传识别、权限控制这三块必须有完整测试用例，且上线前必须全部通过。
建议 · 早期不做会造成明显技术债
编码规范文档代码风格、Git 规范、PR 流程 建议 1 人开发时不重要，2 人以上协作时立刻变成痛点。最低限度：ESLint/Prettier 配置、Git commit 格式（Conventional Commits）、分支策略、PR 必须 Code Review 的规定。
UI 设计规范 / Design System颜色、字体、组件库、间距 建议 设计文档附录 A 已覆盖交互规范，但视觉层的 Token（具体色值、字号、圆角数值）还没有。没有 Design System，前端实现和设计稿会持续有细节出入，每次都要对齐很累。
前端技术规格文档组件拆分、状态管理方案 建议 设计文档描述「页面有什么」，这份文档描述「代码怎么组织」。组件如何拆分、全局状态用什么管理（Zustand/Redux/Jotai）、数据请求用什么封装——这些不写清楚，两个前端会写出两套风格。
监控 & 告警方案错误监控、性能监控、告警阈值 建议 上线后没有监控等于盲飞。最低限度：Sentry 接入错误监控、服务器资源告警、支付成功率告警。这份文档描述监控什么、谁来接收告警、告警后的响应流程。
竞品分析报告主要竞品、差异化定位 建议 不是上线必须，但对定价策略、功能优先级、营销文案有直接参考价值。主要竞品：MuseScore、Flowkey、Yousician、Simply Piano，建议在正式上线前完成分析。
性能需求文档响应时间目标、并发量、SLA 建议 OCR 识别和 MusicXML 渲染是两个潜在性能瓶颈。需要提前定义可接受的响应时间目标（如识别 95% 在 10 秒内完成），才能在压测时有判断标准。
可选 · 规模扩大后再做
独立 PRD 文档用户故事、验收标准、成功指标 可选 建议直接在设计文档各模块补充「验收标准」字段，不单独写。等团队 5 人以上、PM 和设计师职责分离时再拆。
OKR / 项目里程碑计划季度目标、关键结果、时间节点 可选 对于单一创始团队，用 Linear/Notion 里的 Issue 列表管理任务就够了。有投资人或多团队协作时才需要正式 OKR 文档。
商业计划书市场规模、收入模型、融资计划 可选 融资时需要，自研自用阶段不是开发必须文档。
用户研究报告访谈记录、可用性测试结果 可选 MVP 阶段靠创始人的直觉和快速迭代。有条件时做 5 个用户的可用性测试比写正式报告更有价值。
灰度发布方案流量分配、功能开关、A/B 测试 可选 早期用户量少，灰度的意义有限。用户量超过 1 万后再引入。
运维手册 Runbook日常运维操作、故障处理指引 可选 创始人自己运维时脑子里有这些内容。有专职运维或外包运维时才需要成文。
CHANGELOG / Release Notes版本迭代记录、Breaking Changes 可选 上线后维护，面向用户的功能更新说明。初期可以直接用微信公众号推送代替。
